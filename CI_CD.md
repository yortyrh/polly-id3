# CI/CD Pipeline Documentation

## Overview

This project uses GitHub Actions for continuous integration and deployment. The pipeline includes comprehensive testing, code quality checks, security scanning, and automated deployments.

## Workflows

### 1. Main CI Pipeline (`ci.yml`)

**Triggers:**
- Push to `main` or `develop` branches
- Pull requests to `main` or `develop` branches

**Jobs:**

#### 🧪 Test and Coverage
- Runs on Node.js 16, 18, and 20
- Executes all unit tests with coverage reporting
- Uploads coverage reports to Codecov
- Comments PRs with coverage information
- Coverage threshold: 80% for all metrics

#### 🔍 Lint and Format Check
- ESLint for code quality and consistency
- TypeScript compilation check
- Prettier formatting validation
- Ensures code style consistency

#### 🛡️ Security Audit
- npm audit for dependency vulnerabilities
- Snyk security scanning
- Moderate and high severity checks
- Fails CI on high-severity issues

#### 🏗️ Build and Package
- TypeScript compilation
- Serverless framework packaging
- Artifact generation for deployment
- Uploads build artifacts

#### 🚀 Deploy to Staging
- Automatic deployment on `develop` branch
- AWS credentials configuration
- Smoke tests after deployment
- Environment: `staging`

#### 🚀 Deploy to Production
- Automatic deployment on `main` branch
- AWS credentials configuration
- Smoke tests after deployment
- Environment: `production`

#### 🎯 Quality Gates
- Coverage threshold validation
- Bundle size analysis
- Quality report generation
- Overall quality scoring

#### 📢 Notify Team
- CI summary generation
- PR comment with results
- Always runs (even on failure)

### 2. Status Check (`status.yml`)

- Updates project status after CI completion
- Generates status badges
- Commits status updates to repository

## Prerequisites

### GitHub Secrets

The following secrets must be configured in your GitHub repository:

```bash
# AWS Credentials
AWS_ACCESS_KEY_ID=your_aws_access_key
AWS_SECRET_ACCESS_KEY=your_aws_secret_key

# Security Scanning
SNYK_TOKEN=your_snyk_token

# Code Coverage (Optional)
CODECOV_TOKEN=your_codecov_token
```

### Environment Setup

1. **Node.js**: Version 16, 18, or 20
2. **npm**: Latest stable version
3. **AWS CLI**: Configured with appropriate permissions
4. **Serverless Framework**: Installed globally

## Local Development

### Running Tests

```bash
# Run all tests
npm test

# Run tests with coverage
npm run test:coverage

# Run tests with coverage threshold check
npm run test:coverage:check

# Run smoke tests for staging
npm run test:smoke:staging

# Run smoke tests for production
npm run test:smoke:production
```

### Code Quality

```bash
# Lint code
npm run lint

# Fix linting issues
npm run lint:fix

# Check formatting
npm run format:check

# Fix formatting
npm run format:fix

# TypeScript compilation check
npm run build
```

### Quality Reports

```bash
# Generate quality report
npm run quality:report

# Generate CI summary
npm run ci:summary

```

## Coverage Requirements

The CI pipeline enforces the following coverage thresholds:

- **Functions**: 80%
- **Lines**: 80%
- **Statements**: 80%

## Troubleshooting

### Common Issues

1. **Coverage Below Threshold**
   - Add more test cases
   - Ensure all code paths are tested
   - Check for untested edge cases

2. **Linting Errors**
   - Run `npm run lint:fix`
   - Check ESLint configuration
   - Verify Prettier settings

3. **Security Vulnerabilities**
   - Update dependencies
   - Review Snyk reports
   - Address high-severity issues first

4. **Build Failures**
   - Check TypeScript compilation
   - Verify all dependencies
   - Check Node.js version compatibility
