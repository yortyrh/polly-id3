# Architecture

This document describes the architecture of the Polly ID3 Tag Manager application.

## System Overview

The Polly ID3 Tag Manager is a serverless application built on AWS that automatically generates speech audio using Amazon Polly and applies ID3 metadata tags to the resulting MP3 files.

## High-Level Architecture

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│  Direct Lambda  │───▶│  Lambda (id3)   │───▶│   AWS Polly     │
│   Invocation    │    │                 │    │                 │
└─────────────────┘    └─────────────────┘    └─────────────────┘
                                │
                                ▼
                       ┌─────────────────┐
                       │   S3 Bucket     │
                       │  (Audio Files)  │
                       └─────────────────┘
                                │
                                ▼
                       ┌─────────────────┐    ┌─────────────────┐
                       │   SNS Topic     │───▶│ Lambda (Task    │
                       │ (Notifications) │    │  Completed)     │
                       └─────────────────┘    └─────────────────┘
```

## Components

### 1. Lambda Functions (Direct Invocation)
- **Purpose**: Lambda functions are invoked directly via AWS SDK
- **Function**: Used by n8n workflows and other applications
- **Configuration**: Auto-generated by Serverless Framework

### 2. Lambda Functions

#### `id3.handler`
- **Purpose**: Initiates text-to-speech synthesis with ID3 metadata
- **Trigger**: Direct Lambda invocation via AWS SDK
- **Input**: `{ text: string, key: string, id3?: ID3Metadata, override?: boolean, ... }`
- **Output**: Task ID, status, and monitoring commands
- **Timeout**: Configurable (default: 120 seconds)
- **Memory**: Configurable (default: 512 MB)

#### `id3.pollyTaskCompleted`
- **Purpose**: Processes SNS notifications when Polly synthesis completes
- **Trigger**: SNS topic `PollyTaskCompletedTopic`
- **Functionality**: Applies ID3 tags to generated MP3 files
- **Timeout**: Configurable (default: 120 seconds)
- **Memory**: Configurable (default: 512 MB)

#### `id3.updateId3Metadata`
- **Purpose**: Updates ID3 metadata for existing MP3 files in S3
- **Trigger**: Direct Lambda invocation via AWS SDK
- **Input**: `{ s3Bucket: string, folderKey: string }`
- **Timeout**: Configurable (default: 900 seconds)
- **Memory**: Configurable (default: 1024 MB)

### 3. AWS Polly
- **Purpose**: Text-to-speech synthesis service
- **Features**: Neural voices, SSML support, multiple languages
- **Output**: Audio files in MP3, OGG, or PCM format
- **Integration**: Asynchronous task-based processing

### 4. S3 Bucket
- **Purpose**: Storage for audio files and metadata
- **Structure**: Configurable bucket name via environment variables
- **Access**: Lambda functions have read/write permissions
- **Lifecycle**: Files persist until manually deleted

### 5. SNS Topic
- **Name**: `PollyTaskCompletedTopic`
- **Purpose**: Notifications for Polly task completion
- **Subscribers**: `id3.pollyTaskCompleted` Lambda function
- **Created**: Automatically by CloudFormation

## Data Flow

### 1. Audio Generation Flow

```
1. Client Request → AWS SDK → Lambda (id3.handler)
2. Lambda → AWS Polly (StartSpeechSynthesisTask)
3. Lambda → Client (Task ID and monitoring commands)
4. AWS Polly → S3 (Audio file)
5. AWS Polly → SNS (Task completion notification)
6. SNS → Lambda (id3.pollyTaskCompleted)
7. Lambda → S3 (Apply ID3 tags)
8. Client → AWS CLI → Check task status
9. Client → npm run sync-bucket → Download files
```

### 2. Metadata Update Flow

```
1. Client Request → AWS SDK → Lambda (id3.updateId3Metadata)
2. Lambda → S3 (Read existing MP3 file)
3. Lambda → Process ID3 tags
4. Lambda → S3 (Write updated MP3 file)
5. Lambda → Client (Success response)
```

### Network Security
- **VPC**: Lambda functions can run in VPC if needed
- **Encryption**: All data encrypted in transit and at rest
- **Access Control**: Least privilege principle applied

## Performance Characteristics

### Scalability
- **Auto-scaling**: Lambda functions scale automatically
- **Concurrency**: Configurable concurrency limits
- **Throughput**: Limited by AWS service quotas

### Latency
- **Cold Start**: ~100-500ms for Lambda functions
- **Processing**: 1-15 minutes depending on audio length
- **Network**: Minimal latency for S3/SNS operations

### Cost Optimization
- **Lambda**: Pay per request and execution time
- **Polly**: Pay per character synthesized
- **S3**: Pay per GB stored and transferred
- **SNS**: Pay per message published

## Monitoring and Observability

### CloudWatch Metrics
- **Lambda**: Invocation count, duration, errors
- **S3**: Request count, latency, errors
- **SNS**: Message count, delivery success rate
- **Polly**: Character count, synthesis time

### Logging
- **Lambda Logs**: Function execution logs
- **S3 Access Logs**: File access patterns
- **CloudTrail**: API call audit trail

### Alarms
- **Error Rate**: Alert on high error rates
- **Duration**: Alert on slow processing
- **Cost**: Alert on unexpected costs

### Retry Logic
- **Exponential Backoff**: Configurable retry attempts

- **S3 Errors**: Permission or quota issues

- **Network Errors**: Connectivity issues
